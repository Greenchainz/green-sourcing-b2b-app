GreenChainz

Information Security & Risk Management Policy

Version 1.0  ·  Effective: April 19, 2026  ·  Review cycle: Annual  ·  Owner: CEO / founder@greenchainz.com

1. Purpose

This policy establishes GreenChainz Inc.'s framework for identifying, assessing, treating, and monitoring information security risks. It ensures that security risks are managed systematically to protect the confidentiality, integrity, and availability of GreenChainz systems and customer data.

2. Scope

This policy applies to all GreenChainz systems, services, data, and personnel — including contractors and third-party service providers who access GreenChainz systems or customer data.

3. Security Principles

  • Least Privilege: Access to systems and data is granted only to those with a demonstrated need, scoped to the minimum required.
  • Defense in Depth: Multiple layers of security controls are applied rather than relying on any single control.
  • Secure by Default: New features and services are designed with security controls in place from the start, not added afterward.
  • Zero Trust: No system or user is implicitly trusted; all access is authenticated and authorized.
  • Transparency: Security posture, policies, and incident history are documented and available to customers upon request.

4. Risk Management Process

4.1 Risk Identification

Risks are identified through the following activities, conducted at least annually and following any significant change:

  • Review of automated vulnerability scan results (Snyk, Trivy, GitHub Dependabot)
  • Review of security incident and near-miss logs
  • Assessment of new features, integrations, and infrastructure changes
  • Review of third-party security advisories and CVE disclosures relevant to the GreenChainz stack
  • External penetration testing findings

4.2 Risk Assessment and Ranking

Each identified risk is assessed using two factors: Likelihood (probability of occurrence) and Impact (consequence if it occurs). Risks are ranked as follows:

Risk LevelCriteriaResponse SLA
CriticalHigh likelihood + High impact (e.g., RCE vulnerability, exposed DB credentials)Remediate within 24 hours
HighHigh likelihood + Medium impact, or Medium likelihood + High impactRemediate within 7 days
MediumMedium likelihood + Medium impact, or Low likelihood + High impactRemediate within 30 days
LowLow likelihood + Low/Medium impactRemediate within 90 days or accept with documented rationale

4.3 Risk Treatment

For each identified risk, one of four treatment options is selected:

  • Mitigate: Implement controls to reduce the likelihood or impact (preferred for Critical/High risks)
  • Accept: Formally document acceptance of the risk with rationale (only for Low risks)
  • Transfer: Shift risk to a third party (e.g., cyber insurance, contractual liability)
  • Avoid: Discontinue the activity that creates the risk

4.4 Risk Register

All identified risks are recorded in the GreenChainz Risk Register, maintained by the CEO. The register captures: risk description, likelihood, impact, risk level, treatment decision, remediation owner, target remediation date, and current status. The register is reviewed quarterly.

5. Security Controls

5.1 Access Control

  • All production systems require multi-factor authentication (MFA)
  • Access to Azure resources is governed by Azure RBAC with least-privilege role assignments
  • Secrets and credentials are stored exclusively in Azure Key Vault — never in code or environment files committed to version control
  • Employee access is reviewed upon role change and revoked within 24 hours of departure

5.2 Vulnerability Management

  • Automated dependency vulnerability scanning runs on every pull request and on a quarterly schedule via GitHub Actions
  • Container image scanning (Trivy) runs on every Docker build
  • GitHub Dependabot is enabled for all repositories with auto-PR creation for security updates
  • An annual penetration test is conducted using automated scanning tools against the production environment
  • Critical and High CVEs are patched within the SLAs defined in Section 4.2

5.3 Secure Development

  • All code changes are deployed through the GitHub Actions CI/CD pipeline with automated type-checking, linting, and security scanning gates
  • OWASP Top 10 vulnerability classes are addressed during development (injection, broken auth, sensitive data exposure, etc.)
  • TypeScript strict mode is enforced across the codebase to eliminate a class of runtime errors
  • Input validation is applied on all API endpoints using Zod schema validation
  • SQL injection is prevented by using Drizzle ORM query builder exclusively — no raw SQL strings

5.4 Data Protection

  • All data in transit is encrypted using TLS 1.2 or higher
  • Data at rest is encrypted using AES-256 on Azure-managed disks and databases
  • Customer data is stored exclusively in the United States (Azure East US region)
  • Data retention and disposal follows the schedule documented in the GreenChainz Privacy Policy

5.5 Monitoring and Logging

  • Application errors and performance anomalies are monitored in real time via Sentry with automatic alerting
  • Azure Monitor captures infrastructure-level events including authentication failures and network anomalies
  • Logs are retained for a minimum of 90 days
  • Alerts for critical security events are automatically routed to the CEO

6. Third-Party Risk

All third-party service providers with access to GreenChainz systems or customer data are assessed prior to onboarding. Assessment criteria include data handling practices, security certifications, and contractual data processing obligations. Third-party risk is reviewed annually or upon significant change to the provider relationship.

7. Annual Security Review

GreenChainz conducts a formal annual security review each April. The review covers: risk register update, policy review and update, vulnerability scan results, incident log review, access control audit, and assessment of any regulatory changes. Findings are documented and tracked to resolution. The next scheduled review is April 2027.

8. Policy Violations

Violations of this policy are treated as serious matters and addressed promptly. Any employee, contractor, or partner who becomes aware of a policy violation must report it immediately to security@greenchainz.com.
