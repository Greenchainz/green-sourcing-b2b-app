Security at GreenChainz

We build GreenChainz with security as a first principle — protecting supplier credentials, project data, and procurement information for every user on the platform.

Infrastructure & Hosting

☁️

Microsoft Azure

GreenChainz runs entirely on Microsoft Azure (East US region) — Azure Container Apps, Azure Database for PostgreSQL, Azure Container Registry, and Azure Key Vault.

🔒

Encryption

  • TLS 1.2+ for all data in transit
  • AES-256 encryption at rest for all databases and storage
  • HTTPS enforced on all endpoints — no plain HTTP
🗝️

Secret Management

All credentials, API keys, and secrets are stored in Azure Key Vault. No secrets are committed to source code or stored in environment files in version control.

🌐

Network Security

Azure-managed firewall and DDoS protection at the network boundary. Container Apps ingress is restricted to HTTPS only. Internal services communicate over private Azure networking.

Authentication & Access Control

🪪

Microsoft Entra ID SSO

GreenChainz integrates with Microsoft Entra ID (Azure AD) for enterprise single sign-on. Users authenticate via the Microsoft identity platform with PKCE OAuth 2.0 flow.

📱

Multi-Factor Authentication

MFA is enforced on all code repositories (GitHub), DNS management, and credential/key stores (Azure Key Vault). All admin access requires MFA.

🎯

Least Privilege Access

Azure RBAC restricts access to the minimum required. Role hierarchy (admin → architect → supplier → public) is enforced on every API endpoint.

🔑

Session Security

Sessions use signed HttpOnly JWT cookies. Tokens are short-lived and validated server-side on every request. No credentials are stored in browser localStorage.

Development & Code Security

🚦

CI/CD Security Gates

Every pull request runs automated type-checking, linting, dependency vulnerability scanning, and container image scanning before code reaches production. Builds that fail security gates are blocked.

🛡️

OWASP Top 10

Secure coding practices address all OWASP Top 10 vulnerability classes. SQL injection is prevented by using Drizzle ORM exclusively. All API inputs are validated with Zod schemas.

🔍

Vulnerability Scanning

Automated dependency scanning (Snyk) and container image scanning (Trivy) run on every build and on a quarterly schedule. GitHub Dependabot creates automatic PRs for security updates.

📋

Change Management

All code changes are deployed through a GitHub Actions pipeline with required status checks. No direct deployments to production — every change goes through the CI/CD gate.

Monitoring & Incident Response

👁️

Real-Time Monitoring

Sentry monitors application errors and anomalies in real time. Azure Monitor tracks infrastructure metrics and authentication events. Alerts are automatically routed for immediate triage.

📝

Event Logging

All system components emit structured logs retained for a minimum of 90 days. Logs cover authentication events, API access, data mutations, and deployment activity.

🚨

Incident Response

GreenChainz maintains a formal Incident Response Plan covering detection, containment, investigation, user notification, and post-incident review. Data breaches are reported to supervisory authorities within 72 hours of detection.

🔄

Disaster Recovery

Azure-managed automated backups with point-in-time restore for the PostgreSQL database. Container images are versioned in Azure Container Registry enabling rapid rollback.

🔍 Responsible Disclosure

If you discover a security vulnerability in GreenChainz, please report it to us before disclosing it publicly. We commit to acknowledging your report within 48 hours, keeping you informed as we investigate, and resolving confirmed issues promptly.

Report vulnerabilities to: security@greenchainz.com

Please include: description of the vulnerability, steps to reproduce, potential impact, and any supporting evidence. We do not pursue legal action against researchers who follow responsible disclosure guidelines.
